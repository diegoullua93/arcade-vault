## Architecture notes

- App Router only (`app/`); no `pages/`, no `src/`. Path alias `@/*` maps to the repo root.
- `next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `experimental.agentFeedback`. `cacheComponents` changes caching/dynamic-rendering semantics, so consult the docs before fetching data or using request APIs in components.
- Tailwind v4 is wired through Turbopack: a `turbopack.rules` entry in `next.config.ts` runs `@tailwindcss/turbopack` on `*.css`. Styling is configured in CSS (`@import "tailwindcss"` and `@theme inline` in `app/globals.css`), not in a `tailwind.config` file. Dark mode follows `prefers-color-scheme` via CSS variables.
- The root layout uses the globally available `LayoutProps<"/">` type (no import) and loads Geist fonts via `next/font/google`.
- Supabase clients live in `lib/supabase/`: `client.ts` (Client Components) and `server.ts` (Server Components/Actions/Route Handlers, async, reads cookies). Always call `createClient()` per request; never keep a client in a module-level constant or global. Config comes from `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (see `.env.example`); no secret/service_role key is used. No tables or Auth yet.
- Game engines live in `lib/games/` (`types.ts` shared; one folder per game, e.g. `asteroids/`). An engine is plain TypeScript with no React/Next imports: `createXGame(canvas, callbacks)` keeps all state in its closure and returns `{ pause, resume, restart, destroy }`; `destroy()` must cancel rAF and remove every listener. `components/game/game-screen.tsx` (Client Component) creates the engine in `useEffect`, returns `destroy` as cleanup, and mirrors the HUD via `onHudChange`. To add a game: new engine folder, register it in `ENGINES` (game-screen) and in `PLAYABLE_GAME_IDS` (`lib/games.ts`). Scores are not persisted yet.
- TypeScript is `strict`; ESLint extends `eslint-config-next` core-web-vitals + typescript.
