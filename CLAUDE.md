## Architecture notes

- App Router only (`app/`); no `pages/`, no `src/`. Path alias `@/*` maps to the repo root.
- `next.config.ts` enables `cacheComponents`, `partialPrefetching`, and `experimental.agentFeedback`. `cacheComponents` changes caching/dynamic-rendering semantics, so consult the docs before fetching data or using request APIs in components.
- Tailwind v4 is wired through Turbopack: a `turbopack.rules` entry in `next.config.ts` runs `@tailwindcss/turbopack` on `*.css`. Styling is configured in CSS (`@import "tailwindcss"` and `@theme inline` in `app/globals.css`), not in a `tailwind.config` file. Dark mode follows `prefers-color-scheme` via CSS variables.
- The root layout uses the globally available `LayoutProps<"/">` type (no import) and loads Geist fonts via `next/font/google`.
- Supabase clients live in `lib/supabase/`: `client.ts` (Client Components) and `server.ts` (Server Components/Actions/Route Handlers, async, reads cookies). Always call `createClient()` per request; never keep a client in a module-level constant or global. Config comes from `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (see `.env.example`); no secret/service_role key is used. No Auth yet (the session is a mock in `SessionProvider`, `localStorage` key `av_user`).
- Database (Supabase, schema in `supabase/migrations/`, applied with `apply_migration`): `games` (catalog, 8 rows, read-only) and `scores` (public read; public insert only with `is_seed = false`; no UPDATE/DELETE), plus view `game_stats` (`security_invoker`, `best`/`plays` per game) and functions `get_leaderboard` / `get_player_best` (best score per player name, case-insensitive). RLS is on in the same migration that creates each table. Scores are identified by player name, not user (no Auth), so anyone with the publishable key can insert any name; this is accepted until the Auth spec. Types are generated in `lib/supabase/database.types.ts` (regenerate after schema changes). The 70 `is_seed` rows cover the 7 non-playable games; `asteroids` only has real scores. The build now needs `NEXT_PUBLIC_SUPABASE_*` because `generateStaticParams` reads `games`.
- Reads live in `lib/queries/`: `games.ts` (`getGames`/`getGame` are `use cache` with `cacheTag("games")` and long `cacheLife`; `getGamesWithStats` adds dynamic `game_stats`) and `scores.ts` (`getLeaderboard`, dynamic, never cached; dates formatted on the server in UTC/`es-ES`). Anything inside `use cache` must use `createAnonClient()` from `lib/supabase/anon.ts` (no cookies, created per call); dynamic reads use the cookie-aware `server.ts` client under `<Suspense>`. Pages pass data to Client Components (`Library`, `HallOfFame`, `GameCard`) via props; "Tu mejor marca" is the only client-side query (`get_player_best` with the browser client, by session name).
- Saving scores: `GameScreen` calls the Server Action `saveScore` (`app/juegos/[id]/jugar/actions.ts`) once per game when `onHudChange` reports `gameover`, only with a session and score > 0 (guests see a link to `/auth`). `saveScore` validates against `lib/leaderboard.ts` limits and `PLAYABLE_GAME_IDS`, inserts, reads the rank with `get_player_best`, and `revalidatePath`s `/salon` and `/juegos/{id}`. It is not a security barrier (the DB `CHECK`s and RLS are). The status (`GUARDANDO` / `GUARDADO #N` / `ERROR` + `REINTENTAR`) is React in the CRT bottom bar; the engine is untouched.
- Game engines live in `lib/games/` (`types.ts` shared; one folder per game, e.g. `asteroids/`). An engine is plain TypeScript with no React/Next imports: `createXGame(canvas, callbacks)` keeps all state in its closure and returns `{ pause, resume, restart, destroy }`; `destroy()` must cancel rAF and remove every listener. `components/game/game-screen.tsx` (Client Component) creates the engine in `useEffect`, returns `destroy` as cleanup, and mirrors the HUD via `onHudChange`. To add a game: new engine folder, register it in `ENGINES` (game-screen) and in `PLAYABLE_GAME_IDS` (`lib/games.ts`), and add its row to `games`. Scores are persisted (see above).
- TypeScript is `strict`; ESLint extends `eslint-config-next` core-web-vitals + typescript.
